# Finalize 工作流

把初稿当作事实底稿。只改表达，不擅自改变论点、证据强度或信息边界。

## 1. 冻结不可改字段

开始前列出数字、日期、人名、产品名、链接、引文、专业术语和必要限定词。最终必须逐项对回原稿。

## 2. 六个窄检查面

1. **意图与立场**：核心判断是否尽早出现；删掉无意义铺垫，只在原稿已有立场时把它说清楚。
2. **结构与阅读顺序**：合并重复章节；标题、列表和表格只在帮助读者时保留。
3. **具体表达**：把抽象名词还原为具体人物、动作、对象和后果；没有证据的细节不新增。
4. **节奏与温度**：长短句有变化；删掉礼貌填充、假热情、固定转场和每段金句。
5. **格式清理**：去掉装饰性 emoji、每段一个标题、无意义加粗、聊天模型残留和搜索引用脚手架。
6. **完整性复核**：逐项恢复因润色误删的限定词，确认所有冻结字段未变。

轻量任务只做 1、3、5、6；长文或明显模板化内容做完整六遍。

## 3. 定点复查

能使用本地文件时运行：

```bash
python ai-proofreading/scripts/anti_ai_gate.py path/to/draft.md
```

修正 `error`，逐条判断 `warning`。最多两轮。不要因为一个命中项重写整篇文章。

## 4. 边界评分

难判断时按 1–10 分评估：

- 直接：不预告自己将要说什么。
- 节奏：句长和段落压力不匀速。
- 信任：不替读者解释显而易见的内容。
- 真实：用词像被作者选择过。
- 密度：每句话都有必要。

总分低于 35/50，再做一次定点修改。

## 5. 返回前检查

- 核心判断更早、更短或更清楚。
- 没有为了口语化而编造个人经历。
- 没有为了增强立场而删掉必要不确定性。
- 格式符合发布场景，而不是一律去掉 Markdown。
- 定稿比原稿更短或更锋利，而不是仅仅换了一套措辞。
