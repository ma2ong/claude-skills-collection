# 场景预设

场景决定内容形态，作者画像决定声音。事实、引用和平台规则始终优先。

## 公众号 / 博客 / Newsletter

- 论点在前，背景随后；前三段必须给继续阅读的理由。
- 允许有信息作用的 H2/H3、代码块、图片和引用。
- 手机阅读段落保持紧凑，但不机械限制每段行数。
- 收尾落到读者能带走的判断或下一步，不做行业未来式升华。
- 删除“话不多说”“希望本文有所帮助”和堆叠的点赞关注提醒。

## 社交短帖

- 第一屏直接给判断、场景或反常识事实。
- 不使用 Markdown 标题层级；数据和名称保持精确。
- 允许不完整句和少量语气词，但不制造错别字或漏掉关键信息。
- 平台有长度、emoji 或 hashtag 习惯时服从平台规则。

## 专业报告 / 技术文档

- 保留帮助检索和复用的标题、列表、表格、代码块。
- 结论明确；不确定性用条件、区间或概率表达。
- 写清选择、放弃和原因，不把取舍藏进“综合考虑”。
- 不为了口语化替换必要术语，也不使用 emoji 装饰。

## 冲突处理

1. 事实、合规和用户明确要求。
2. 作者画像中的禁忌与术语。
3. 场景格式约束。
4. 作者节奏和标点习惯。
5. 通用去 AI 味建议。
