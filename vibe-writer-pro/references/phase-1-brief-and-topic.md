# Phase 1 · 需求理解与选题策划

> 本文件是 `vibe-writer-pro/SKILL.md` 的分册。执行本阶段前必须完整读完；
> 主文件只保留骨架与检查清单，跳过本文件等于跳过本阶段的质检。

### 🎯 Phase 1: 需求理解与选题策划 (Brief & Topic)

**步骤 1.1 - 理解需求**

当用户说"我想写一篇关于 XX 的文章"时：

1. 提问关键信息：
   - 目标读者是谁？（技术人员/产品经理/普通用户）
   - 文章目标？（教程/观点/案例分析/新闻解读）
   - 长度预期？（短文 1000 字/中长文 2000-3000 字/长文 5000+ 字）
   - 发布平台？（公众号/知乎/个人博客）
   - 特殊要求？（技术深度/风格偏好/时效性）

2. **判断写作模式**（影响后续调研策略）：

| 触发词 | 判断结果 | 调研模式 |
|-------|---------|---------|
| "热点"、"时事"、"最新"、"刚发生"、"昨天"、"今天"、"这两天" | 热点新闻模式 | hotspot-collector + Agent Reach，时效窗口 24–72h |
| "新闻解读"、"事件分析"、"某公司刚宣布" | 热点新闻模式 | 同上 |
| "教程"、"指南"、"怎么用"、"原理"、"深度" | 深度研究模式 | Web 搜索，时效窗口 6 个月 |
| 用户直接提供文章/材料 | 直接写作模式 | 跳过调研，直接进入 Phase 2 |

3. 输出需求理解：
```
【需求理解】

目标读者：[读者画像]
文章类型：[类型]
核心目标：[要解决什么问题/传递什么价值]
预估长度：[字数]
发布平台：[平台]
写作模式：[热点新闻 / 深度研究 / 直接写作]
```

**步骤 1.2 - 调研（根据模式分叉）**

---

### 模式 A：热点新闻模式

**时效窗口：72 小时内。超时内容不引用。**

**第一步：调用 `hotspot-collector`**

- 先运行 Agent Reach 体检，按 `active_backend` 采集当前可用渠道。
- 使用 `hotspot-collector/references/research-routing.md` 的 fallback，不硬编码单一 OpenCLI 路径。
- 输出必须包含 `source_coverage`、实际后端、可靠性和检索时间。

**第二步：调用 `evidence-researcher`**

对进入正文的关键事实补一手来源。社交热度只能提供角度或争议，不能单独证明事实。

**第三步：时效性过滤**
- 只保留 72 小时内的内容
- 跨平台出现 ≥ 2 次的话题优先
- 标记 🔥 突发事件（0–24h）

**第四步：调用 `personal-knowledge-search`** 查找相关个人素材

输出热点调研报告：
```
【热点调研完成】

采集平台：X 个
有效热点条目：X 条
时效分布：X 条（0-24h）/ X 条（24-72h）
跨平台验证：X 条同时出现在 2+ 平台

核心热点：
1. [热点标题] — [来源平台] — [发布时间] — [简介]
2. [热点标题] — [来源平台] — [发布时间] — [简介]
3. [热点标题] — [来源平台] — [发布时间] — [简介]

个人素材：X 条
```

---

### 模式 B：深度研究模式

**时效窗口：6 个月内**

- 调用 `evidence-researcher` 查找**最新信息**、真实案例、一手来源和反方观点
- 收集**数据支撑**（统计数据、报告、论文），并记录实际检索后端与时间
- 搜索**竞品内容**（了解已有角度），但不把社交观点写成事实
- 调用 `personal-knowledge-search` 查找用户的个人素材库

输出调研报告：
```
【调研完成】

找到相关资料：X 篇
真实案例：X 个
数据支撑：X 条
个人素材：X 条

核心发现：
1. [发现 1]
2. [发现 2]
3. [发现 3]
```

---

### 模式 C：直接写作模式

用户已提供材料（文章链接、文档、截图等）：
- 阅读并理解全部材料
- 调用 `personal-knowledge-search` 查找相关素材
- 直接进入 Phase 1.3 选题生成

**步骤 1.3 - 选题生成**

基于调研结果，生成 3 个差异化选题方向：

```
【选题提案】

根据调研，我为你准备了 3 个选题方向：

---

### 选题 1：[标题]

**核心角度**：[一句话说明独特视角]

**为什么值得写**：
- [理由 1 - 填补市场空白/解决实际问题]
- [理由 2 - 有充足素材支撑]

**预估工作量**：[短/中/长]

**文章大纲**：
1. [章节 1]
2. [章节 2]
3. [章节 3]

---

### 选题 2：[标题]
...

---

### 选题 3：[标题]
...

---

请选择你感兴趣的选题编号（1/2/3），或告诉我需要调整的方向。
```

**选题设计原则**：
- 3 个选题必须有**明显的角度差异**
- 每个选题有**足够的素材支撑**
- 标题**有吸引力但不标题党**
- **HKR 质检门槛**（每个选题必须过，未过线不提案）：
  - **H (Happy/有趣)**：足够有趣有悬念，标题让人想点开？
  - **K (Knowledge/信息量)**：读者能学到新东西？
  - **R (Resonance/共鸣)**：能戳中情绪引发认同？
  - 及格线：两项满足。S 级选题三项全中。

---

**步骤 1.4 - 材料门槛（写长文的准入条件，不过不许动笔）**

选题定了以后、动笔之前，先在内部数材料。**这一步不能跳。用户催"直接写"也不能跳。**

| 计划字数 | 材料下限 |
|---------|---------|
| ≥ 1200 字 | ≥ 5 件具体材料 |
| ≥ 3000 字 | ≥ 8 件具体材料，且能组成 2 条以上完整过程 |

材料还要能串成一条实际过程，不能是五句相邻的道理。

**什么算一件材料**（每件必须能写出来路）：

| 类型 | 出处怎么写 |
|-----|----------|
| 用户提供的经历、动作、原话、数字、判断 | 用户说的哪一句话 |
| 查到并能核验的案例、数据、产品流程、人物经历 | 具体来源链接或文件 |
| 自己跑过的代码、试过的产品、截过的图 | 我实际做了什么 |

**什么不算材料**（这些是模型在自我繁殖，不能撑篇幅）：

- ❌ "比如有个人……"——临时想出来的典型场景
- ❌ 一个抽象观点推演出来的用途、意义、风险、未来
- ❌ 同一件事换四种说法
- ❌ 比喻、类比、同义改写
- ❌ 只写一个概括性类别（"很多开发者反馈体验不好"不算一件；"某某在 issue #123 里列了三条具体问题"算一件）

> **判据**：三条抽象想法，分别补上用途、意义、风险、未来，写成十几段，手里**仍然只有三条**。推理可以连接材料，不能自己繁殖成材料。

**材料不够时只能三选一，不许硬凑字数**：

1. **能查就查。** 有公开材料可查却没查，等于没有材料。查完重新数。
2. **必须问就问，一次问完，最多 3 个问题**，此时不要同时交稿：
   - 你和这件事实际发生过什么关系？
   - 哪个瞬间、数字、动作或原话最让你在意？
   - 你现在最想说的判断是什么？
3. **用户不让问、要求直接写**：缩小题目，交一篇 600 字左右的短稿，把材料边界说清楚。

> **宁可明显短于目标字数，也不能用假例子和重复解释填满。**
> 字数是目标，材料是底线。底线压不过目标。

**输出格式**（内部检查，达标就直接进 Phase 2，不用汇报；不达标才告诉用户为什么写不了长文）：

```
【材料清点】

计划字数：X 字 → 需要 X 件
已有材料：X 件

1. [材料] ← 出处：[用户原话 / 来源 / 我做过什么]
2. ...

状态：✅ 达标 / ⚠️ 差 X 件 → [去查 / 问 3 句 / 缩到 600 字]
```
