# 开头优化原则（完读率闸门）

> 为什么重要：标题决定**打开率**（进不进推荐池），开头决定**完读率**（推不推得更广）。公众号算法看完读——开头 2-3 句留不住人，推荐立刻停。这是 0 流量的第二个杀手。

## 5 条底层原则

1. **开头是内容试用装，不是标题附属物**：读者常在没有标题语境下先碰到前几句。开头必须**独立成立**，不能假设读者已经看懂标题。
2. **强开头不能靠"先把答案说完"**：抛出问题、冲突、结果、反差，让人想往下看。把结论放开头 = 没人需要读正文。
3. **必须建立在真实素材上**：没有数据、案例、反差、立场、场景感，开头的冲击力受限。空泛铺垫（"在这个时代…"）是完读率第一杀手。
4. **口播/阅读顺滑度单独判断**：有些句子看着像金句，念出来很别扭。公众号读者是默读，长句堆叠一样劝退。
5. **方案成组出现**：不是给一句最好的，是给几种可比较的开局方向，再选和正文气质最配的。

## 开头诊断 6 个检查点

发布前对照检查现有开头：

- **独立性**：脱离标题还成立吗？
- **抓手**：前两句有没有一个具体的钩子（问题/数字/冲突/场景）？
- **悬念/张力**：读者读完第一段，有没有"想知道后面"的动力？
- **可信度**：凭什么信你？（身份、案例、数据三选一）
- **顺滑度**：默读一遍卡不卡？有没有 AI 翻译腔（见 `ai_fingerprints.md` #19）？
- **兑现关系**：开头抛的钩子/标题的悬念，正文接住了吗？接不住就是标题党，掉完读率。

## 5 种开局方向（按正文气质选）

| 开局方式 | 怎么开 | 适合什么正文 |
|---|---|---|
| **结果前置** | 把最反常识的结果/数字甩在第一句 | 案例驱动、变现、效率类 |
| **冲突/反差** | 制造"这不对吧"的认知冲突 | 观点、科普、破误区 |
| **场景代入** | 描述读者此刻的真实处境 | 解决方案、人群向 |
| **悬念缺口** | 抛一个不剧透答案的问题 | 揭秘、行业内幕 |
| **故事切入** | 一个有具体细节的真实片段（人名、时间、出错） | 经验、逆袭、长文 |

## 红线

1. 正文太弱时，别假装"只改开头"就能救——回去补素材。
2. 别生成和正文无法兑现的开头（标题党的代价是完读率）。
3. 别只给一句话，给可比较的方向。
4. **诊断先于生成**：先说清当前开头差在哪，再给方案。
