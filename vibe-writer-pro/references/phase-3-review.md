# Phase 3 · 统一审校（含 3.5 发布前质检关）

> 本文件是 `vibe-writer-pro/SKILL.md` 的分册。执行本阶段前必须完整读完；
> 主文件只保留骨架与检查清单，跳过本文件等于跳过本阶段的质检。

### 🔍 Phase 3: 统一审校 (Unified Review)

**步骤 3.1 - 第一遍：内容审校**

检查以下内容：

- [ ] **事实准确性**：核实所有数据、日期、人名、产品名
- [ ] **逻辑清晰性**：论证链条完整，没有逻辑跳跃
- [ ] **无编造信息**：不编造不存在的引用、数据、案例
- [ ] **原创性**：不是直接复制网络内容
- [ ] **完整性**：每个观点都有支撑，每个承诺都有交付

输出：
```
【第一遍审校完成】

修正问题：
- [问题 1 及修正方案]
- [问题 2 及修正方案]

状态：✅ 通过 / ⚠️ 需要补充素材
```

**步骤 3.1.5 - 推进检查（专治长文注水）**

第一遍查的是"说得对不对"，这一遍查的是"有没有往前走"。

> **长文最主要的注水形态是把一个观点解释四遍。句子层面的审校抓不到它**，因为每一句单看都没毛病。

**动作 1：给每段标两个内部标签**（不输出给用户）

- **作用**：动作 / 事实 / 例子 / 解释 / 疑问 / 判断 / 背景 / 情绪
- **材料出处**：这段靠哪一件材料托住（对应 Phase 1.4 清单里的编号）

出处只能写出"这是上一段的进一步解释"或"这是可能的影响"，说明这段没有新东西，**删掉或与上一段合并**。

**动作 2：查连续同作用段**

连续 3 段以上标着同一个作用（尤其连续"解释"），通常在拖。留最有材料的那一段。

**动作 3：查后段有没有接住前段**

后一段应当回答前一段留下的问题、动作或结果。整篇靠"更深一层""真正的问题""还有一层"这类路标往前推的，把路标删掉，让事实差异承担连接。删完接不上，说明顺序本来就不对，调整顺序。

**动作 4：压缩试验（硬指标）**

删掉全文三分之一，再读一遍。

- 事实、动作、判断、阅读体验**几乎没变** → 原稿在注水，**保留删短后的版本**
- 明显读不懂了、少了关键因果 → 原稿密度合格，恢复原稿

**动作 5：查背景段**

历史、技术、制度、数据这类段落，问它正在回答哪一个问题。删掉以后判断、风险和结论都不变，说明这段知识来早了，或者根本用不上。

输出：
```
【推进检查完成】

段落总数：X
删除/合并：X 段（只做重复解释）
调整顺序：X 处
删除路标：X 处
压缩试验：⚠️ 删 1/3 后几乎无损失 → 已保留短版 / ✅ 信息损失明显 → 保留原稿

字数变化：X → X
```

**步骤 3.2 - 调用 `ai-proofreading` finalize（核心）**

- 把 Phase 3.1 核实后的正文作为事实底稿。
- 运行 `ai-proofreading` 的 finalize 模式，按发布场景做意图、结构、具体表达、节奏、格式和完整性复核。
- 用户提供本人样本或说“不像我”时，先执行 learn-style。
- 能执行脚本时运行 `ai-proofreading/scripts/anti_ai_gate.py`；只修命中位置，最多两轮。
- 不编造真实细节，不机械删除破折号、列表或 Markdown；按场景与作者画像判断。
- 同时运行 `scripts/check_prose.py`；翻案句、黑话和模型路标属于 error，其他形状 warning 结合作者画像判断。

输出：
```
【统一审校完成】

最终字数：XXX 字
确定性检查：0 errors / X warnings（均已判断）
事实字段复核：✅

【审校后完整文章】

[输出审校后的完整 Markdown 文章]

---

状态：✅ finalize 完成，准备配图
```

**步骤 3.4 - 第四遍：爆款质量门（7维评分）**

> 参考：`references/viral-framework.md`

逐项检查，生成爆款评估报告：

```
【爆款质量门 — 7维评估】

D1 标题与封面    □ / ✅   信息差+情绪触发+具体数字命中 ≥ 2/3？
D2 钩子结构      □ / ✅   前3行给出"这篇和你有关"信号，无铺垫废话？
D3 内容密度节奏  □ / ✅   段落 2-4行，有加粗/编号/金句分层，含可回收干货？
D4 情绪设计      □ / ✅   触发愤怒/焦虑/自豪/感动至少一种，有分享动机设计？
D5 互动引导      □ / ✅   正文埋问题/争议判断，结尾有显式互动引导？
D6 关注转化      □ / ✅   有系列感/资源钩子/人设差异化至少一项？
D7 传播裂变      □ / ✅   至少1个可截图传播的信息单元（金句/数据图/对比表）？

达标：X/7
爆款概率：□ 高（6-7项）/ □ 中（4-5项）/ □ 低（≤3项）

未达标项修复：
- D?: [具体修改动作]
```

**规则**：达标 < 5 项，必须修复后才能进入 Phase 4。

**爆款门增强（公式化升级）**：
- D1 标题：不靠感觉，调用 `references/title_formulas.md` 给标题套公式编号，张力检查至少命中 2 项；产出 3 个备选 + Top 1
- D2 钩子：调用 `references/hook_principles.md` 跑 6 检查点（独立性/抓手/悬念/可信度/顺滑度/与正文兑现）
- 全文：调用 `references/ai_fingerprints.md` 扫 22 条 AI 指纹，命中 🔴 强信号必须按追问表改

**步骤 3.5 - 发布前技术 Preflight（决定能不能稳定进草稿箱）**

> 参考：`references/publish_preflight.md`
> 这一步专治"文章发不出去/排版乱/图片丢/0 推送"的**技术侧**问题，和上面的内容质量门是两回事，缺一不可。

```
【发布前技术 Preflight — 7 项硬检查】

1 正文图素材化     □ / ✅   每张图换成 mmbiz.qpic.cn URL，无外链/本地路径？
2 封面 thumb_media_id □ / ✅   先传封面拿 id 再建草稿？
3 无深色背景白字   □ / ✅   无 background深色+color白 的隐形段落？
4 标题≤64/摘要≤120 □ / ✅   未超长，钩子在前 13 字？
5 IP 白名单        □ / ✅   出口 IP 已加后台白名单？
6 appid/secret 有效 □ / ✅   config.json 凭证未过期？
7 复杂排版降级     □ / ✅   table 已改普通段落？

成功条件：拿到 media_id 才算发布成功（接口没报错 ≠ 成功）。
缺条件 → 诚实降级到本地 preview，保留 errcode，不伪造成功。
```

**规则**：7 项有任一不过，先修配置/图片，别急着 API 重试。
